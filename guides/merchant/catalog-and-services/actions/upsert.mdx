`POST /merchant/v3/{merchantId}/merchantUpsert` cria os objetos cujo `id` ainda não existe na loja e altera os que já existem. Objetos que você não enviar ficam como estão. É a rota para cadastrar produtos, opções e categorias e para manter o catálogo em dia, um tipo por chamada.

<Info>
Como o upsert pode criar objetos, ele exige mais campos que o [update](/guides/merchant/catalog-and-services/actions/update): `name` em todos os tipos com `id`, e `menu`, `price` e `categoryId` em `ITEM`. As regras de formato, imagens e erros comuns às três rotas estão em [Ações](/guides/merchant/catalog-and-services/actions).
</Info>

<Warning>
**Gere um UUID novo para cada objeto no seu sistema.** O `id` enviado vira o ID do objeto na DeliveryVip. Não reaproveite UUIDs de outras plataformas ou de catálogos antigos: se o UUID já pertencer a outra loja, o objeto é ignorado sem erro. Use UUID em minúsculas, versão 1 a 5 (por exemplo, v4).
</Warning>

## Corpo da requisição

<ParamField body="merchantStatus" type="string">
`AVAILABLE` abre a loja, `UNAVAILABLE` fecha. Obrigatório quando não houver `entityType`.
</ParamField>

<ParamField body="entityType" type="string">
Tipo dos objetos em `upsertObjects`: `SERVICE`, `PAYMENT_METHOD`, `OPTION`, `OPTION_GROUP`, `CATEGORY` ou `ITEM`. Um tipo por chamada.
</ParamField>

<ParamField body="upsertObjects" type="object[]">
Objetos a criar ou alterar, no formato do `entityType` ([veja abaixo](#objetos-por-entitytype)). Obrigatório e não pode ser vazio quando houver `entityType`.
</ParamField>

| Você envia | Efeito |
| --- | --- |
| Só `merchantStatus` | Abre ou fecha a loja. |
| `entityType` + `upsertObjects` | Cria ou altera só os objetos enviados. |
| Os três | Faz as duas coisas na mesma chamada. |

## Ordem do cadastro

Um objeto só pode apontar para outro que já existe. Na primeira carga, envie um tipo por chamada nesta ordem:

<Steps>
<Step title="OPTION" icon="circle-dot">
As opções individuais, como sabores e bordas.
</Step>
<Step title="OPTION_GROUP" icon="layer-group">
Os grupos, com `optionIds` apontando para as opções do passo anterior.
</Step>
<Step title="CATEGORY" icon="folder">
As seções do cardápio.
</Step>
<Step title="ITEM" icon="burger">
Os produtos, com `categoryId` e, se tiverem, os modificadores apontando para os grupos.
</Step>
</Steps>

`SERVICE` e `PAYMENT_METHOD` não dependem de nada e podem ir a qualquer momento.

## Requisição

Cadastrar uma categoria:

<CodeGroup>
```bash cURL
curl --request POST 'https://api.deliveryvip.com.br/merchant/v3/{merchantId}/merchantUpsert' \
  --header 'Authorization: Bearer {token}' \
  --header 'Content-Type: application/json' \
  --data '{
    "entityType": "CATEGORY",
    "upsertObjects": [
      { "id": "44b34740-e8a1-44ea-8ef1-c0b896877df3", "index": 1, "name": "Pizzas", "status": "AVAILABLE" }
    ]
  }'
```

```js Node.js
const response = await fetch(
  `https://api.deliveryvip.com.br/merchant/v3/${merchantId}/merchantUpsert`,
  {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      entityType: 'CATEGORY',
      upsertObjects: [
        { id: '44b34740-e8a1-44ea-8ef1-c0b896877df3', index: 1, name: 'Pizzas', status: 'AVAILABLE' },
      ],
    }),
  },
)
if (response.status !== 204) console.error(await response.json())
```

```python Python
response = requests.post(
    f"https://api.deliveryvip.com.br/merchant/v3/{merchant_id}/merchantUpsert",
    headers={"Authorization": f"Bearer {token}"},
    json={
        "entityType": "CATEGORY",
        "upsertObjects": [
            {"id": "44b34740-e8a1-44ea-8ef1-c0b896877df3", "index": 1, "name": "Pizzas", "status": "AVAILABLE"},
        ],
    },
)
if response.status_code != 204:
    print(response.json())
```
</CodeGroup>

A resposta de sucesso é `204 No Content`, sem corpo. Veja os [erros possíveis](/guides/merchant/catalog-and-services/actions#respostas-e-erros).

## Objetos por entityType

Em um objeto que já existe, só os campos enviados são alterados. Opções, grupos, categorias e produtos removidos por um [force](/guides/merchant/catalog-and-services/actions/force) voltam ao catálogo se forem enviados de novo com o mesmo `id`.

### SERVICE

<ParamField body="serviceType" type="string" required>
`DELIVERY` (entrega) ou `TAKEOUT` (retirada).
</ParamField>
<ParamField body="serviceTime" type="integer" required>
Tempo do serviço, em minutos.
</ParamField>
<ParamField body="status" type="string">
`AVAILABLE` ativa o serviço, `UNAVAILABLE` desativa. Sem o campo, a disponibilidade atual é mantida.
</ParamField>

<Accordion title="Exemplo" icon="code">
```json
{
  "merchantStatus": "AVAILABLE",
  "entityType": "SERVICE",
  "upsertObjects": [
    { "status": "AVAILABLE", "serviceType": "DELIVERY", "serviceTime": 40 },
    { "status": "AVAILABLE", "serviceType": "TAKEOUT", "serviceTime": 40 }
  ]
}
```
</Accordion>

<ParamField body="id" type="uuid" required>
ID da forma de pagamento.
</ParamField>
<ParamField body="name" type="string" required>

<ParamField body="mode" type="string" required>

### ITEM

<ParamField body="id" type="uuid" required>
ID do produto.
</ParamField>
<ParamField body="name" type="string" required>
Nome do produto.
</ParamField>
<ParamField body="categoryId" type="uuid" required>
Categoria do produto. Precisa existir na loja.
</ParamField>
<ParamField body="menu" type="string[]" required>
Onde o produto é vendido: `DELIVERY`, `TAKEOUT` e `INDOOR`. Um tipo que não vier na lista deixa de valer. `DELIVERY_TAKEOUT` ainda é aceito por retrocompatibilidade e vira `DELIVERY` + `TAKEOUT`. Prefira os tipos individuais.
</ParamField>
<ParamField body="price" type="object" required>
<Expandable title="propriedades">
<ParamField body="value" type="number" required>
Preço atual.
</ParamField>
<ParamField body="originalValue" type="number" required>
Preço original. Quando `value` é menor que `originalValue`, o produto aparece **em promoção**: por exemplo, `value` 80.0 e `originalValue` 100.0.
</ParamField>
<ParamField body="currency" type="string" required>
Sempre `BRL`.
</ParamField>
</Expandable>
</ParamField>
<ParamField body="index" type="integer">
Posição dentro da categoria, a partir de `1`.
</ParamField>
<ParamField body="description" type="string">
Descrição do produto.
</ParamField>
<ParamField body="externalCode" type="string">
Código no seu sistema.
</ParamField>
<ParamField body="status" type="string">
`AVAILABLE` ou `UNAVAILABLE`.
</ParamField>
<ParamField body="ean" type="string">
Código de barras EAN.
</ParamField>
<ParamField body="image" type="object">
`url` (`https://`) e `checksum` da imagem, como em `OPTION`. Veja as [regras de imagem](/guides/merchant/catalog-and-services/actions#imagens).
</ParamField>
<ParamField body="modifiers" type="object[]">
Lista **completa** de modificadores do produto. Substitui a atual.

<Expandable title="propriedades">
<ParamField body="id" type="uuid" required>
ID do modificador.
</ParamField>
<ParamField body="name" type="string" required>
Pergunta exibida ao cliente, por exemplo "Escolha os sabores".
</ParamField>
<ParamField body="index" type="integer">
Posição no produto, a partir de `1`.
</ParamField>
<ParamField body="externalCode" type="string">
Código no seu sistema.
</ParamField>
<ParamField body="status" type="string">
`AVAILABLE` ou `UNAVAILABLE`.
</ParamField>
<ParamField body="rule" type="string">
`ADDITION`, `APPORTIONMENT` ou `HIGHEST`. Veja as [regras de preço](/guides/merchant/catalog-and-services/actions#regras-de-preço-do-modificador).
</ParamField>
<ParamField body="minPermitted" type="integer">
Mínimo de opções. Envie junto com `maxPermitted`.
</ParamField>
<ParamField body="maxPermitted" type="integer">
Máximo de opções. `0` significa sem limite.
</ParamField>
<ParamField body="optionGroups" type="object[]">
Lista **completa** de grupos de opções do modificador. Substitui a atual.

<Expandable title="propriedades">
<ParamField body="optionGroupId" type="uuid" required>
ID de um grupo de opções que já existe na loja.
</ParamField>
<ParamField body="index" type="integer">
Posição do grupo no modificador, a partir de `1`.
</ParamField>
<ParamField body="options" type="object[]">
Preço, posição e status de opções do grupo **neste modificador**.

<Expandable title="propriedades">
<ParamField body="optionId" type="uuid" required>
ID da opção.
</ParamField>
<ParamField body="index" type="integer">
Posição da opção, a partir de `1`.
</ParamField>
<ParamField body="status" type="string">
`AVAILABLE` ou `UNAVAILABLE`.
</ParamField>
<ParamField body="price" type="object">
`value`, `originalValue` e `currency` (`BRL`), todos obrigatórios. O preço cobrado é o `value`.
</ParamField>
</Expandable>
</ParamField>
</Expandable>
</ParamField>
</Expandable>
</ParamField>

<AccordionGroup>
<Accordion title="Como os modificadores são gravados" icon="layer-group">
* `"modifiers": []` remove todos os modificadores do produto. Um modificador que existia e não veio na lista é **apagado**. Sem o campo `modifiers`, os modificadores atuais são mantidos.
* `"optionGroups": []` remove todos os grupos do modificador. Sem o campo, os grupos atuais são mantidos.
* Todas as opções do grupo entram no modificador automaticamente. A lista `options` só ajusta preço, posição e status de cada uma. Uma opção que não faz parte do grupo é ignorada.
</Accordion>

```json
    {

      "categoryId": "44b34740-e8a1-44ea-8ef1-c0b896877df3",

        {
          "id": "2488c7a1-0706-409d-bb69-d248f4c81358",

```

</Accordion>
